# Security policy

Arbiter executes code generated by AI agents. Treat every candidate workspace as hostile.

## Required controls

- Never mount the Docker socket into the API, worker, or sandbox container.
- Never run candidate code with credentials, host mounts, privileged mode, or host networking.
- Use immutable task versions and a verifier directory that the candidate cannot modify.
- Enforce CPU, memory, PID, runtime, workspace-size, and output-size limits.
- Keep provider keys server-side and redact secrets from logs.
- Validate every task path as a relative path within the workspace.
- Keep public task authoring disabled in the single-operator deployment.

## Production sandbox gate

The development Docker runner is intentionally not treated as a production Fargate implementation. The AWS stack provisions a separate, non-public sandbox task definition and gives the worker/API only the narrow task-launch permissions needed to complete the bridge. Operators must implement and review the task bridge, pin the ECR sandbox digest, validate network egress, and run the sandbox smoke suite before enabling public arbitrary task execution.

Please report suspected vulnerabilities privately to the repository maintainer before public disclosure.
